### Patterns observed
- **Agencies in Egypt and the UAE often ship English only.** The ones that do Arabic well (Telfaz11, Hsoub) use a path prefix (`/ar`, `/en`) and write the Arabic natively rather than translating it. A properly written Arabic version is a real differentiator for a solo creator targeting Gulf clients.
- **Proof first:** client logo walls, showreels and named brands come before long bios. Years of experience and "Egypt + Gulf markets" are the standard credibility claims for Egyptian freelancers.
- **Register is stated as a service feature.** Freelancers say "MSA / Egyptian / Saudi-Gulf dialect according to audience". Listing the dialects the creator writes in (Egyptian, MSA, Gulf-friendly) is a selling point.
- **Productized services** on Khamsat (price per script length, bundles, repurposing) show how Arab buyers think: in deliverables such as "Reel script, 30-60s", "content calendar for a month", "design of 12 posts".
- Gulf hirers want to see **side-by-side AR/EN samples and adaptation (transcreation)**, not just translation. A case-study format of "brief → Arabic copy → English copy → result" fits well.
- Use Arabic brand terms naturally: Telfaz11 writes its own name in Arabic script inside Arabic text while keeping the Latin logo.

## 2. Tone: MSA vs Egyptian colloquial

**Evidence**
- Rani Amayri (Impact BBDO), *Handbook of Arabic Copywriting*: "there is nothing called 'White Arabic'". Choose the dialect after choosing the target market. For multi-market GCC work he proposes **"Hybrid Classical Arabic"**, a mild, modern MSA with some colloquial words. Historically, Egyptian was the "hero" dialect for North Africa and for humour, and Saudi for the Gulf. Avoid copy that sounds dated or rigid. https://campaignme.com/the-handbook-of-arabic-copywriting-part-1-by-impacts-rani-amayri/
- 7iber, "Lost in transliteration": headlines and slogans have creative licence, while body copy is expected in MSA. Writing only in heavy classical style makes a brand stiff. https://www.7iber.com/lost-in-transliteration-the-perils-of-arabization/
- Telfaz11 (KSA) uses MSA for corporate copy and dialect inside content titles. Hsoub uses pure MSA. (Sources above.)

**Recommendation for this portfolio**
- **Base register: light, modern MSA** (فصحى مبسطة / "white-ish" MSA). It reads as professional to both Egyptian and Gulf clients, and Gulf clients may find Egyptian colloquial body copy too informal or "local".
- **Use Egyptian colloquial deliberately as a showcase**: in hero micro-lines, script excerpts, reel captions and quoted work, where it shows the creator's voice. Label samples by dialect ("سكريبت بالعامية المصرية").
- Write in the **first person** with a warm voice, avoiding the stiff passive constructions typical of translated corporate copy.
- **Transcreate, do not translate.** Write the AR copy from the brief, not from the EN sentences. Typical tells of translated text: "يتم + مصدر" passives, calques like "قم بـ", stacked "والذي", and English word order in headlines.

**Common pitfalls**
- **Literal translation** of idioms and CTAs ("Let's talk" → "دعنا نتحدث" reads as translated. Better: "تواصل معي", "خلّينا نشتغل سوا" (Egyptian), or "ابدأ مشروعك").
- **Latin punctuation in Arabic text**: use the Arabic comma ، (U+060C), semicolon ؛ (U+061B) and question mark ؟ (U+061F). Don't put a space before them. Avoid English-style serial commas between coordinated words, since Arabic uses و. https://blogs.transparent.com/arabic/punctuation-in-arabic/
- Quotation marks: «» or "" are both used in Arabic. Pick one and use it everywhere.
- **Hamza and taa marbuta slips** (اإأ, ه/ة, ى/ي) are very common in Egyptian typing (e.g. "مصرى" vs "مصري"). Proofread them, because Gulf readers notice.
- **Numerals**: CLDR treats Arabic-Indic digits (٠١٢٣) as customary in Egypt and KSA, but Egyptian and Saudi brand websites (Telfaz11, Hsoub) use **Western digits 0-9**, and so do social platforms. Choose one system and **never mix the two within a page, and above all within a single number**. Arabic-Indic numbers use their own separators (٫ decimal, ٬ thousands, ٪ percent placed before the number). https://github.com/w3c/alreq/wiki/Arabic-numerals-%28Draft%29 ; https://corp.unicode.org/pipermail/cldr-users/2019-April/000918.html ; https://rtlstyling.com/posts/rtl-styling
  - JS gotcha: `Intl.NumberFormat('ar-EG')` and `toLocaleString('ar-EG')` output **Arabic-Indic** digits by default. Use `'ar-EG-u-nu-latn'` (or `numberingSystem: 'latn'`) if the site standardizes on Western digits. The same applies to dates (`Intl.DateTimeFormat`).
- Arabic does not support abbreviations like "Sat" or "Jan". Write full words (rtlstyling).
- Translated strings change length (e.g. "Done" → "تم"), so give buttons a `min-width` (rtlstyling).

### Pairing logic
- Prefer **families designed as Arabic-Latin pairs**: Alexandria ↔ Montserrat, Readex Pro ↔ Lexend, IBM Plex Sans Arabic ↔ IBM Plex Sans, Cairo ↔ Titillium Web. Their stroke weight, x-height and Arabic body proportions are matched.
- If the site already has a distinctive Latin display face (e.g. a serif), don't try to imitate it in Arabic. Pick a clean Arabic sans with a **similar weight and contrast**, and let the layout and colour carry the brand.
- Browsers fall back glyph by glyph, so list the Arabic font in the stack (or swap the stack under `:lang(ar)`) to avoid Arabic text rendering in a system font. https://rtlstyling.com/posts/rtl-styling

### Sizing, spacing and weights
- **Never letter-space Arabic** (`letter-spacing: 0`, and also reset any uppercase/tracking utilities under `[dir=rtl]` / `:lang(ar)`). Tracking breaks the connected letterforms. https://rtlstyling.com/posts/rtl-styling
- **Don't use `text-transform: uppercase`** for Arabic. It has no effect, but the tracking that usually comes with it does damage.
- **Increase line-height** for Arabic (practitioner range: about 10-20% more than Latin, e.g. 1.5 → 1.7-1.8 for body and 1.1 → 1.3 for headings). Arabic has deep descenders and stacked dots and diacritics, and tight leading clips the kasra and dots. https://rtlstyling.com/posts/rtl-styling ; https://freezil-website-wjfnk.kinsta.page/blog/arabic-typography-guide.html
- **Bump Arabic font size** by about 1 step (≈ +10-15%, e.g. 16 → 18px body). Arabic letters have a smaller main body relative to their extenders, so at the same px size they look smaller. The print convention is English 12 with Arabic 14. CSS `font-size-adjust` is x-height based and Latin-centric, so it doesn't solve this. Use explicit `:lang(ar)` overrides instead. https://lists.w3.org/Archives/Public/www-style/2012Mar/0126.html ; https://mlt.proz.com/forum/prozcom_suggestions/137599-larger_font_size_in_arabic.html
- Avoid ultra-thin weights (<300) for Arabic body text and very heavy weights at small sizes, because dots and counters clog. https://rtlstyling.com/posts/rtl-styling
- **No faux bold or italic**: set `font-synthesis: none` for Arabic. Arabic has no italic tradition, so for emphasis use weight, colour or a highlight, never `font-style: italic`. Remove `<em>`/`<i>` italics in the AR locale (`:lang(ar) em { font-style: normal; font-weight: 600 }`).
- **No transparency on Arabic text** (rgba/opacity). Overlapping joins show darker seams. Use a solid colour instead. https://rtlstyling.com/posts/rtl-styling
- **Underlines collide with dots**: use `text-decoration-skip-ink: auto`, a larger `text-underline-offset`, or a border or box-shadow underline. https://rtlstyling.com/posts/rtl-styling
- Justification: avoid `text-align: justify` for Arabic on the web. Browsers widen word spaces rather than using kashida, which looks wrong. Use `start` alignment.
- Check `word-break` / `overflow-wrap` so Arabic words are not split mid-word.

## 4. RTL layout and bidi gotchas

**Document setup**
- `<html lang="ar" dir="rtl">` on `/ar/` pages (with `lang="en" dir="ltr"` on EN pages). Add `lang` to inline foreign spans (`<span lang="en">`), which drives font selection, spellcheck and screen readers. https://www.w3.org/International/articles/inline-bidi-markup/
- Add `hreflang` alternates (en / ar, and optionally ar-EG or ar-SA) between page pairs.

**Logical CSS**
- Use `margin-inline-start/end`, `padding-inline-*`, `inset-inline-*`, `border-inline-start`, `text-align: start/end`, and `border-start-end-radius`. Flexbox and grid flip automatically. Floats, absolute offsets and `translateX` animations do not, so handle them per direction (`[dir=rtl] { --dir: -1 }` and `translateX(calc(var(--dir) * 100%))`). Tailwind has `ms-/me-/ps-/pe-/start-/end-` and the `rtl:` variant. https://rtlstyling.com/posts/rtl-styling
- Carousels and horizontal scrollers: the start position and the "next" direction flip, and scroll offsets (`scrollLeft`) are negative in RTL in modern browsers. Test any reel or gallery slider.

**Icons**
- **Mirror** directional icons: back/forward and next/prev arrows, chevrons in buttons ("View work →" becomes ←), breadcrumbs, "send" (debated), list/indent icons, non-media progress bars, and the reading order of steps or timelines.
- **Don't mirror**: media play/pause/seek and video progress bars (they represent tape direction), clocks and refresh icons, checkmarks, search (magnifier), logos, social brand icons, physical objects, numbers, charts, and the slash in icons. https://m1.material.io/usability/bidirectionality.html ; https://firefox-source-docs.mozilla.org/_sources/code-quality/coding-style/rtl_guidelines.rst.txt
- Implementation: `[dir=rtl] .icon-directional { transform: scaleX(-1) }`, or swap the icon component.

**Mixed bidi text**
- Wrap opposite-direction runs tightly. Use `dir="ltr"` on known-LTR items such as **emails, URLs, phone numbers, @handles, prices with currency codes and code**, e.g. `<a href="tel:+20..." dir="ltr">+20 10 1234 5678</a>`. Use `<bdi>` or `dir="auto"` for runtime or unknown strings such as client names, project titles from data and tags. https://www.w3.org/International/articles/inline-bidi-markup/
- Without isolation, "+20" becomes "20+", trailing punctuation jumps to the wrong side, and English brand names at the end of an Arabic sentence pull the period away.
- Where markup is impossible (`<title>`, `alt`, `aria-label`, `meta description`) use the isolate controls FSI/LRI/RLI…PDI (U+2068/U+2066/U+2067…U+2069), or `&lrm;`/`&rlm;`. Avoid the older embeddings (LRE/RLE/PDF). (W3C, same source.)
- **Form inputs**: email, phone and URL fields stay `dir="ltr"` with left alignment. Arabic placeholders are right-aligned. Use `dir="auto"` on free-text message fields. https://rtlstyling.com/posts/rtl-styling
- Phone numbers with spaces can reorder in RTL. Either isolate them with `dir="ltr"` or use hyphens or dots. https://github.com/w3c/alreq/wiki/Arabic-numerals-%28Draft%29
- Latin brand and tool names (Premiere Pro, CapCut, Canva, TikTok) inside Arabic sentences are fine. Wrap them in `<span lang="en">` (or `<bdi>` if they end the sentence) so the period and spacing stay correct.

**Other**
- Scrollbars do not move to the left side in RTL. Don't design around that assumption. https://rtlstyling.com/posts/rtl-styling
- Video and reel embeds: keep player controls LTR. Captions and titles around them are RTL.
- Charts and stats keep LTR axes, while labels are translated.
- Test with real Arabic copy, not lorem ipsum or machine translation. Line lengths, wrapping and diacritic clipping only show up with real text.

## Recommended Arabic font pairing for this portfolio

**Primary recommendation (variable, Egyptian pedigree, modern creative feel)**
- **Arabic display/headings: Alexandria** (variable 100-900), Arabic companion of Montserrat, by the Egyptian designer Mohamed Gaber. Use 600-800 for headings.
- **Arabic body/UI: Readex Pro** (variable 160-700, plus the HEXP axis), the Arabic of Lexend, built for readability. Use 400 for body and 500-600 for labels.
- Both are variable, so you need about 2 font files for the whole Arabic UI. Load via `next/font/google` with `subsets: ['arabic']` and apply them only under `:lang(ar)` / the `/ar` layout.
- Latin harmony: if the EN site's fonts are free to change, Montserrat/Lexend match these exactly. Otherwise keep the existing Latin faces and simply swap families per locale.

**Conservative alternative**: IBM Plex Sans Arabic (body, static weights) + Alexandria or Fustat (headings), especially if the EN site uses IBM Plex Sans or another neutral grotesque.

**Accent only (sparingly)**: Lalezar or Baloo Bhaijaan 2 for one playful display word, Marhey for handwritten notes, and Amiri for a pull-quote or script excerpt.

**Suggested CSS tokens for AR**
```css
:lang(ar) {
  --font-display: "Alexandria", "Noto Sans Arabic", system-ui, sans-serif;
  --font-body: "Readex Pro", "Noto Sans Arabic", system-ui, sans-serif;
  letter-spacing: 0;          /* never track Arabic */
  font-synthesis: none;       /* no faux bold/italic */
}
:lang(ar) body { font-size: 1.0625rem; line-height: 1.8; }  /* ~17-18px, +line-height */
:lang(ar) h1, :lang(ar) h2 { line-height: 1.3; letter-spacing: 0; text-transform: none; }
:lang(ar) em, :lang(ar) i { font-style: normal; font-weight: 600; }
:lang(ar) a { text-underline-offset: .35em; text-decoration-skip-ink: auto; }
```
